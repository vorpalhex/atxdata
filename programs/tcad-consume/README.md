# TCAD source selection and importer

## CLI frontend contract

The source entrypoint is `bun /absolute/path/to/this/program/src/cli.ts COMMAND [OPTIONS]`; it does not depend on the caller's working directory. There is no newly installed binary. `--help`, `-h`, `help COMMAND`, and `COMMAND --help` / `COMMAND -h` are offline informational paths on stdout, status 0, without opening archive state. Plain invocation and missing input fail with usage on stderr, status 1; nothing prompts or consumes stdin. `--version` before the command reports the newly declared CLI/package identity 0.1.0, not an upstream release or data version. Package dependencies are unchanged.

All operational options are command-local and follow the command; there are no operational global options to move before it. Required values support both `--key=value` and `--key value`. Options may be reordered; repeated options, empty values, unknown names and arbitrary abbreviations are rejected rather than guessed. Only `-h` has a short spelling; grouped/attached short options are not supported. Recognized help bypasses unrelated parse failures, but a required value spelling `--help` is not help. A split value starting `--` is rejected as a missing value; use `--key=VALUE` for an option-like literal. `--` ends options in the command scope; these commands accept no file operands, so following operands are rejected without interpreting them as help. A trailing `--` alone is allowed. Bun 1.3.14 itself consumes a separator immediately after the script path: to deliver a top-level separator use `bun src/cli.ts -- -- TOKEN`; normally put the separator after a command, e.g. `bun src/cli.ts list -- --help` (an operand error, not help). This runtime-boundary limitation cannot be recovered from the argv delivered to the program.

Operational success remains exactly one JSON document with one newline on stdout, with the existing schema and no decoration, pagination or progress mixed into it. Help/version are plain text exceptions. Parser/domain failures remain status 1 on stderr without expected-error stacks; diagnostics identify option names without echoing values or arbitrary record-like operands. Retained source files are canonical regular files (ZIP inputs must be seekable), not stdin streams; `-` is not an archive input/output convention. `--output` names the existing private durable archive root, not a JSON destination. Redirect stdout normally for JSON. No new color, prompt, pager, quiet or framework controls are implied.

Checked stdout writes retain the bounded 16 KiB partial-write/backpressure loop with a ten-second EAGAIN deadline. EPIPE (early consumer closure) preserves historical status 1 and a concise stderr diagnostic; other output failures, including EBADF, also fail status 1. No Bun source excerpts/stacks are emitted.

Completed checkpoint/archive work is not erased when result delivery fails; inspect status and verify before retrying. A delivered result does not itself certify every archived record's semantics. Pure frontend selection/budget/conflict checks run before Store/Collector opening, with library guards retained. Existing policy/history/locks are not reset or adopted. SIGINT uses native process termination (POSIX Python status -2, commonly shell status 130); a lock and interrupted/pending evidence can remain. Establish the writer is dead and review private evidence before any operator recovery; the CLI never auto-removes a stale lock. Local checkpoint cancellation is tested, not automatic remote resume or repeated-signal/remote-child cleanup guarantees.

The shipped `test/frontend.test.ts` invokes `test/frontend_native.py` (Python 3 stdlib) through the absolute Bun executable, from an unrelated private cwd with isolated HOME/XDG/TMPDIR and EOF. It checks independent stdout/stderr/status/state, all help paths, token context, equals/split forms, invalid/repeated/numeric/conflicting inputs, legacy JSON, real local catalog/import/verify/reuse, nonblocking slow-pipe large JSON, inherited read-only stdout (EBADF), closed-reader pipes and bounded SIGINT/lock refusal. Fixture directories and per-case receipts remain under explicitly supplied canonical TMPDIR outside checkouts, including on failure. Run all tests behind OS public-network denial; only existing authored loopback fixtures need a localhost exception. Standalone: `BUN=/absolute/path/to/bun python3 test/frontend_native.py`. Source entrypoint behavior is exercised on macOS arm64/Bun 1.3.14; Linux/Windows, installed binaries/uninstall, full mixed PTYs, exhaustive filename encodings/permissions and live remote cancellation remain unverified. No public acquisition is part of these regressions.

TCAD `--refresh` continues to require explicit `true` or `false`; string false is never refresh permission. Positive safe-integer controls retain Number-compatible syntax, including `1e2` and `0x1`, rather than narrowing to decimal digits. `--count all` remains explicit. Legacy `list`/`import`/`inventory`/`integrity`/`status`/`verify` remain distinct from general member/catalog commands.

Bun/TypeScript + SQLite, with Python 3 standard-library OOXML parsing. Poppler `pdftotext` remains required for the backward-compatible legacy sample alias. TCAD is the appraisal district, not the County Tax Office.

## General local selection

From this directory, install cached dependencies with `bun install --frozen-lockfile --offline`. Inputs must be canonical absolute paths without symlinks. Use one private, owned, mode-0700 output root outside every checkout; retain original inputs at their registered paths. The existing exclusive archive writer lock is shared with the legacy store. Never remove an uncertain/stale lock automatically.

    bun src/cli.ts inventory-members --archive "$ZIP"
    bun src/cli.ts layouts --layout "$LAYOUT_ZIP"
    bun src/cli.ts import-member --archive "$ZIP" --layout "$LAYOUT_ZIP" --snapshot 2026-certified-supp0 --member PROP.TXT --start 101 --count 30 --max-expanded 2097152 --max-seconds 30 --output "$OUTPUT"
    bun src/cli.ts member-status --output "$OUTPUT"
    bun src/cli.ts verify-members --output "$OUTPUT"

`--snapshot` is an operator label, not an assertion that a remote historical export exists. Any compatible local year/supplement/archive can be selected. Hashes are calculated per input, never checked against a global allowlist in this path. `--layout` is optional: omitted or unmatched classes retain raw bytes without claiming interpretation. Use the exact inventory member name, including any directory prefix; schemas match exact published short names, not guessed aliases.

Records are one-based newline-delimited original byte sequences, including CRLF or LF; an unterminated final record is retained. `--count all --start 1` streams a complete member. An integer count selects exactly that many records or fails, returning `next` for explicit continuation at a later `--start`. Starting later necessarily decompresses preceding bytes again, which count against `--max-expanded`. No random-access/byte-resume protocol is invented for compressed members. Each range is an independent coverage version, not an assertion that disjoint ranges comprise a complete roll. Rerunning an identical complete selection verifies and reuses it.

SQLite persists every selected record's original BLOB, member (via version identity), ordinal, raw SHA256, positional original field strings, and quarantine reason. It inserts batches of 500, not a full-member array. A version is complete only after the final status/hash/coverage checkpoint; failed/interrupted rows and versions remain evidence and are not silently promoted. Retrying failed work creates another attempt; there is no deletion of history. Incomplete attempts are visible in member-status. The general tables are additive; legacy versions/downloads/rows/runs remain unchanged. Existing general-member versions without independent selection receipts are retained, not silently retro-certified: verification/reuse requires operator review. A new explicit import selection can coexist without deleting the old archive/history.

Complete streaming consumes and validates member length and CRC. `complete` means exactly start=1/count=all/EOF; finite counts never imply complete coverage. `crcVerified` is a separate persisted fact: finite unterminated EOF and suffix-all selections can verify the entire input stream CRC without retaining the entire member. Early-stopped prefixes do not claim whole-member CRC, including on reuse. `verify-members` rehashes compressed originals, reparses selected workbook schemas, validates inventory, positional decoding, row hashes and aggregate coverage. Partial selections also compare each ordinal and original BLOB against a bounded re-read of the retained selected range (preceding decompression still counts), not just mutually editable database hashes. Selection identity and original run limits have an independent append-only receipt; missing or changed bindings fail closed. Complete coverage also reconciles stored raw bytes to the original member size/CRC without decompressing the whole archive again. These are integrity/schema checks, not adjudicated business semantics or unique-property counts.

## Layout coverage

The retained Legacy8.0.33 ZIP has a Property-only PDF (493 fields) and a workbook with 20 class sheets. The workbook, not the single PDF shape, drives general schemas. Formats include fixed-width and tab-delimited tables; duplicate filler names are preserved positionally. No fixed year, supplement or positive-valuation rule is imposed on general rows. Numeric values remain original strings; malformed widths/numerics/non-ASCII are quarantined, never dropped.

Observed workbook limitations are reported rather than repaired by guessing: PROP_ENT's freeze_ceiling_override declares start/end2645 but length15; LAND_DET jumps from byte28 to39. Those schemas are marked noncontiguous and their rows retained/quarantined without interpreted-success claims. The workbook advertises SKETCH.TXT while the retained archive has SKETCH_INFO.TXT; that exact-name mismatch is raw-only. The retained totals PDF has no typed record schema. Other workbook classes are schema-capable, but only Property and StateCode were exercised on real retained records in this repair; do not equate schema enumeration with complete semantic verification of all classes.

## Published catalog and explicit acquisition

    bun src/cli.ts discover --output "$OUTPUT" --max-requests 2 --max-bytes 2097152
    bun src/cli.ts catalog --output "$OUTPUT"
    bun src/cli.ts acquire --output "$OUTPUT" --id "$CATALOG_ID" --max-requests 2 --max-bytes 671088640
    bun src/cli.ts acquire --output "$OUTPUT" --id "$CATALOG_ID" --max-requests 2 --max-bytes 671088640 --refresh true

Discovery reads robots and the official https://traviscad.org/publicinformation page, using a nonexecuting standard-library HTML parser (comments/script/style/template/noscript content excluded) to enumerate actual same-authority `/wp-content/largefiles/*.zip` links. Select an exact returned catalog ID; there is no guessed year/URL synthesis. Acquisition streams the selected published ZIP to a private exclusive pending file, validates bounded ZIP inventory, hashes it and promotes without clobber. Positive safe request/byte budgets and intact persisted policy are validated even for cache hits. A cached acquisition verifies its official URL-derived ID, exact artifact path, actual byte length/SHA256, and independent immutable catalog/acquisition observation binding before zero-request reuse. `--refresh true` explicitly makes a fresh observation at the same published URL; it never replaces prior original bytes. New version-qualified artifacts and append-only acquisition history coexist with the current-cache pointer, request ledger and existing cooldown. Omitted `--refresh` (or `false`) retains zero-request reuse. Missing historical acquisition provenance requires operator review; files are never adopted by filename alone. It does not import automatically; select its local path/member explicitly afterward. JSON/EARS/improvement exports can be cataloged/acquired as ZIPs; their data is NOT thereby claimed interpreted by this fixed/tab importer.

Discovery retains the original HTML, response headers/status/source URL, observation time and parsed catalog membership in append-only provenance tables. HTTP contexts must name the exact discovery route, status200 and valid header pairs, and reference their completed successful producing request with matching immutable body SHA256, byte count and headers. Contexts are runtime-validated on insertion and cache verification; same-authority unrelated/error responses are not published catalog evidence. Retained local HTML imports are labeled operator-import with unknown HTTP status/headers; they are not authenticated live discovery, even if the operator obtained the file from the publisher. For retained discovery HTML (offline, no freshness claim):

    bun src/cli.ts catalog-import --html "$RETAINED_PUBLICINFORMATION_HTML" --output "$OUTPUT"

Exported discover/acquire operations serialize per database filename as well as under the archive root lock. A transactional reservation rereads current policy, cooldown and unfinished ledger after every awaited sleep, waiting again if obligations changed. Requests are serial, with persisted start/end/status/byte/error ledger, minimum three-second completion-to-start delay, stricter robots delay (observed10seconds), Retry-After after success/failure, and conservative24-hour holds on RateLimit-family headers. Numeric X-RateLimit Reset values have fixed epoch-seconds semantics, while non-X Reset values are relative seconds; an epoch expiring during body consumption never becomes a massive relative duration on completion/reopen. The same interpretation is used for producing and reconciling obligations, with the24-hour floor unchanged. Older ambiguous evidence is not retro-certified or used to shorten an existing gate; contradictions still require operator review. Explicit per-command request/byte budgets are not lifetime quotas and do not erase cooldown/history. No redirects, automatic retries, cookies, authentication or challenge bypass. Unknown unfinished requests, uncertain promotion states and existing partials require operator review. Missing/deleted/invalid singleton policy rows, unsafe cooldown timestamps/delays, malformed robots state and corrupt or unfinished request history stop before reservation/reuse/transport; a deleted row is never recreated as new permission. Persisted delay must also meet the minimum and retained robots Crawl-delay, not merely have an integer shape. Nonmutating preflight runs before existing-state schema work, offline verification/import history and catalog writes too. Missing live tables, including the request ledger/evidence/format marker, fail closed rather than being reconstructed. Fresh or genuine legacy-only archives initialize separately; the format2 migration preserves existing ledger/history and adds no invented old response receipts. Completed-request times and independently retained immutable headers are also reconciled against the numeric gate: a well-typed lower timestamp cannot erase Retry-After, minimum/robots spacing or RateLimit-family holds, even after restart. Contradictions reject before reopen/schema work, cache/offline history or reservation, without rewriting the gate or policy. Completed historical requests without available response evidence require operator review; empty legacy-only history remains compatible. Robots are cached in the source archive; changing policy requires operator review rather than silently discarding persisted policy. Do not use a second output root to evade pacing. Public network capability is explicit only in discover/acquire; tests inject transports under OS network denial.

Fresh bounded discovery observed11 published ZIP links: layout; 2026 certified fixed-width and JSON; supplemental335; special supplement3; five EARS year-labeled files; improvement detail. No historical certified-roll endpoint was observed. Metadata availability is not proof that every advertised ZIP currently downloads. The original implementation made two metadata requests; chief subsequently exercised native discovery with two successful HTTP200 metadata attempts and eleven catalog rows. This independent repair made zero public requests and downloaded no public archives; it reused the certified557228168-byte and layout248399-byte retained originals. The acquire implementation was exercised with local ZIP response fixtures, not a fresh public archive transfer.

## Bounds and compatibility

ZIP safety remains:640MiB compressed inputs,1MiB compressed layout,64 members,20GiB total declared expansion,10GiB/member, safe paths, no symlinks/special/encrypted/unsupported-method members. General records have a1MiB ceiling; batch memory is at most500 bounded raw records plus stream/parser state. Decoded values/SQLite require additional disk and bounded batch memory; no18GiB array is created. Caller-supplied expanded/time budgets apply to each member read. A finite integer count does not infer completeness even if it happens to end at EOF. Raise a run budget explicitly rather than resetting policy.

The historical commands `list`, `import`, `inventory`, `integrity`, `status`, `verify` retain their original pinned first25 contract for existing archives and callers. They are legacy aliases, NOT the only supported mode and NOT general status/verification. In particular, `list` retains its historical response for compatibility; use catalog and inventory-members for general discovery. Legacy first25 selection is `2026-certified-supp0-property-first25`; pinned archive/layout hashes remain only its provenance contract. No repeat full18GiB integrity pass was performed.
