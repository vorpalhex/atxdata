## Browser procedure

Use the general agent-browser skill through the terminal tool. Use an explicit reviewed config, unique owned local session and a fresh private download directory outside the repository. Normal browser subresources/concurrency are allowed; searches and exports remain deliberate. No Power BI request/token replay or hidden-model extraction is needed.

1. Open the portal, choose Vendor Payment Details and wait for the actual Power BI controls/table rather than generic network idle. Record the destination, selected fiscal year, payment-date bounds, other filters, report page and source update label privately. The observed defaults were fiscal year 2027, October 3, 2022–November 4, 2026, page 1 of 2, updated November 5, 2026 at 04:39 (publisher label; timezone unspecified).
2. To inspect one actual payment, take its identifier from a displayed source row. Open Payment #, locate the Search textbox from the current snapshot and fill the whole ID. Wait for that exact selectable option, select it, then close the dropdown. Search initially showed temporary No results/old options while loading; neither proves the payment is missing. Do not confuse searching the dropdown with applying its selection.
3. Wait for BOTH the payment slicer and the result table to agree. The verified payment `2001441678` showed two rows with opposite amounts and a zero total. The immediate post-click snapshot still showed old broad rows; only the settled snapshot was used for reconciliation. Preserve masked invoice text, blanks, negative amounts, string IDs and leading-zero line items; do not infer duplicate rows from payment number/line item alone. Departments/categories can differ.
4. Native right-click selected a row rather than opening an export menu. Escape and a normal second click on the same selected cell cleared it; both final row-selection checkboxes were unchecked. Do not assume a context-menu action is harmless to selection state. Refresh and verify state after exploratory clicks.
5. The visible **Export per Fiscal Year** control exports the whole selected fiscal-year file, NOT just the payment/other table slicers. Authorize that larger file scope before clicking. It is not a bounded payment-row export. In this task, one FY2027 file was obtained; no other fiscal year or second report page was fetched. Native button text may be exposed to accessibility only as a generic Web URL link. An accessibility-link click did not produce an observed file; the visually located Export per Fiscal Year button was activated with ordinary mouse input. Do not copy screenshot coordinates across layouts—inspect the current screenshot.
6. After an uncertain command, inspect the private download directory and browser before retrying. The native mouse-up command timed out, but `PaymentRegister_2027.csv` had completed in the fresh task directory. No second export was issued. Require the expected file to be stable and no `.crdownload` partial to remain. Retain the original bytes unchanged and set private permissions. No pretransfer network byte cap was enforced by this browser button; the observed file was 3,211,435 bytes. Do not claim a cap or HTTP/MIME/download receipt that was not captured.
7. Hash the original, decode UTF-8 with optional BOM, and parse with a CSV reader keeping fields as strings. Check the actual header, every row width, fiscal-year/date sets, amount syntax and the selected payment's field association. Treat schema/malformed records as source-quality findings, not permission to silently shift columns, drop records, overwrite the original or claim the file is clean. Save any derived validation/row extracts privately, separate from source bytes.
8. Compare the selected payment against the settled UI across every displayed data column. Omit Row Selection: it is a UI control, not a CSV field. Keep Description as an additional CSV field, and account for UI-vs-CSV date/currency formatting explicitly. Use decimal currency arithmetic, not binary float. A matching two-row view establishes only that sample's agreement; it does not prove the report/file has no omitted or differently aggregated payments.
9. Close only the owned browser session. Offline reuse checks the retained hash and parsed facts without a new source call; it is not freshness validation. Any later fiscal-year snapshot must use a fresh destination and observation date. No unattended retries, history crawler, database, restart/resume engine or complete archive is implemented.
